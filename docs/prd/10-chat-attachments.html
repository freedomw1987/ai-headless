3. 資料模型

3.1 Attachment 模型（Prisma Schema）

model Attachment {
  id           String   @id @default(cuid())
  sessionId    String
  session      ChatSession @relation(fields: [sessionId], references: [id], onDelete: NoAction, onUpdate: NoAction)
  filename     String   // 原始檔名
  mimeType     String   // e.g. "application/pdf"
  size         Int      // bytes
  storagePath  String   // ./uploads/<sessionId>/<uuid>.<ext>
  uploadedAt   DateTime @default(now())
  
  @@index([sessionId])
  @@index([uploadedAt])
  @@map("attachments")
}
3.3 設計決策
  • onDelete: NoAction — 永久保留機制，session 刪除不級聯附件
  • storagePath 存相對路徑，部署可掛不同磁碟
  • mimeType + filename 雙欄位防偽造
  • 無 deletedAt 在 Attachment — session 才軟刪除

4.5 上傳後端流程圖

[User] 點 [📎 附加檔案] 選檔
   ↓
[前端] 檢查 MIME + 大小（client-side guard）
   ├─ 超 10 MB → toast「檔案過大」
   ├─ MIME 不符 → toast「不支援的格式」
   └─ 通過 → 開始上傳
   ↓
[前端] POST /api/admin/chat/upload (multipart/form-data)
   ↓
[後端 Guard] auth.js 中間件 → hasDynamicPermission('admin')
   ├─ 非 admin → 回 403 Forbidden
   └─ admin → 繼續
   ↓
[後端 Handler] multipart parser → 逐檔檢查
   ├─ MIME server-side 驗證（讀 magic bytes）
   ├─ 大小 server-side 驗證（10 MB 上限）
   └─ 通過 → 寫檔到 ./uploads/<sessionId>/<uuid>.<ext>
   ↓
[後端 Handler] 寫 Attachment table
   ↓
[後端 Handler] 回 200 + { attachments: [...] }
   ↓
[前端] chips 顯示「✓ 已上傳」

我想要 上傳 PDF 檔案並問 AI「這份報告的重點」

以便 AI 讀取 PDF 內容並摘要

驗收標準：

  • 點 📎 選 PDF（≤10 MB）

  • 輸入「這份報告的重點？」並送出
  • AI 回應引用 PDF 內容（具體文字 / 段落）

驗收標準：

  • 上傳 PNG / JPG（≤10 MB）
  • AI 回應：「這張截圖顯示的是 XXX 錯誤訊息...」
  • Reasoning 區顯示「識別圖中文字 + 分析錯誤類型」
